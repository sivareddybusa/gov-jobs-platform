Security rules

These are mandatory:

Never trust client-supplied user IDs.
Never trust client-supplied roles.
Never trust client-supplied permissions.
Never trust client-supplied eligibility results.
Never expose the Supabase service-role key to the browser.
Never bypass RLS for convenience.
Resolve authenticated users server-side.
Validate server inputs with Zod.
Use database constraints where appropriate.
Keep sensitive operations server-side.
Preserve the existing RLS model.
Preserve audit/history protections.
Treat government documents as untrusted input.
Treat AI output as untrusted candidate data.
AI must never directly decide final eligibility.
Protect all server-side URL fetching against SSRF.
Do not execute uploaded or downloaded documents.
Eligibility rules

The eligibility engine must remain deterministic.

The final decision must come from structured rules + user profile data.

Possible results:

eligible
not_eligible
needs_verification

Never guess when rules or profile data are ambiguous.

Age must be calculated from DOB against the job-specific cutoff date.

Do not use today's date when the job provides an age cutoff.

Category and special statuses remain separate concepts.

Do not collapse them into one field.

State and domicile remain distinct.

Qualification matching remains AND-of-OR groups.

AI may extract candidate rules, but the deterministic eligibility engine decides the result.
